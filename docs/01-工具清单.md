### 2.2 各类工具的适用场景与成本

#### ① Agentic CLI（Claude Code / Codex CLI / Gemini CLI）—— **本项目的主力**

**适用场景**：任何"改代码 + 跑起来验证"的循环。它是唯一能让 AI **自己跑 `godot --headless --check-only` 看有没有语法错、自己跑测试脚本、自己根据报错再改**的形态。对不会写代码的团队来说，这个闭环就是全部生产力。

**为什么特别适合 Godot**：Godot 的场景 `.tscn`、资源 `.tres`、脚本 `.gd` 全是纯文本，CLI 工具能直接读写；`--headless` 又让它可以无界面跑测试。换成 Unity 就没这么顺。

**成本（2026-10 官方价）**：

- Claude Code：包含在 Claude 订阅里。Pro 档 **$20/月（月付）或 $17/月（年付，$200 一次性付清）**；重度使用上 Max，**从 $100/月起**。
- Codex CLI：包含在 ChatGPT 付费订阅里（**Plus $20/月**起），也可用自己的 OpenAI API Key 按量计费。
- Gemini CLI：有免费额度，适合作为"零成本备用"。

**注意**：CLI 工具是**按用量限流**的，不是无限用。重度使用（一天改 30 个文件）大概率会撞到限额，这也是为什么很多人要上 Max 档。

#### ② AI IDE（Cursor / Windsurf）—— **最适合"看 diff"的人**

**适用场景**：需要**可视化审查 AI 改动**的时候。AI IDE 的 diff 视图、逐块接受/拒绝、一键回滚，对"我不写代码但我必须看懂改了什么"的角色非常友好。**建议团队里至少有一台机器用 AI IDE**，专门负责审 diff。

**成本（2026-10 官方价）**：

- Cursor：Free $0（额度有限）/ Plus **$8/月** / Premium **$30/月** / Super $100/月 / Ultra $200/月。年付有折扣（Plus $80/年，Premium $300/年）。
- Windsurf：Free $0 / Pro **$20/月** / Max $200/月 / Teams（含团队费）。

**注意**：这类工具近年改成了"额度池"模式，**同一句提示词消耗多少额度取决于模型和任务**，实际月成本很难精确预估。建议先买最低档试一个月，用真实项目跑一遍看够不够。

#### ③ VS Code + GitHub Copilot —— **补全为主，对本项目价值有限**

**适用场景**：你在**手写**代码时它很有用（补全、行内建议）。但本项目"人不写代码"，所以它的核心卖点（代码补全）对你们用处不大。它的 **agent 模式**能干活，但整体能力弱于 ① 和 ②。

**成本（2026-10 官方价）**：Free $0 / Pro **$10/月** / Pro+ $39/月 / Max $100/月（每用户每月）；Business $19/席位/月，Enterprise $39/席位/月。额度以"AI Credits"计（Pro 基础 1,000 + 弹性 500）。

**但有一个理由值得装**：VS Code 是**看代码和看 diff 最轻量的工具**，装 Copilot 免费档也能用对话问"这段代码在干什么"。**如果预算只有一份，把这份钱花在 ① 上，VS Code 用免费档。**

#### ④ 网页版对话（ChatGPT / Claude / DeepSeek）—— **必备的辅助，不能当主力**

**适用场景**（这几件事网页版做得比 CLI 更好）：

1. **问概念**："Godot 的 `Area2D` 和 `CharacterBody2D` 有什么区别？"——比让 CLI 翻文档快。
2. **翻译报错**：把 Godot 输出面板的英文报错贴进去，让它解释成人话。
3. **生成占位素材的描述**：让它写"生成 16 个像素风格的中式武器图标的提示词"。
4. **写策划文档**：把口头规则整理成表格、写数值设计文档。
5. **写提示词**：让一个 AI 帮你把需求改写成更清楚的提示词，再喂给 CLI 工具。

**成本（2026-10 官方价）**：

- ChatGPT：Free $0 / Go $8/月 / Plus $20/月 / Business $20/用户/月。
- Claude：Free $0 / Pro **$20/月（年付 $17/月）** / Max 从 $100/月。
- **DeepSeek**：有免费网页版，API 按量计费（价格见 <https://api-docs.deepseek.com/zh-cn/quick_start/pricing>）。**国内访问无障碍、中文理解好、便宜**，非常适合作为"日常问答 + 报错翻译"的零成本方案。

**注意**：网页版最大的问题是**代码进不了你的仓库**。你让它写 5 个文件，你要手动创建 5 个文件、逐个粘贴、还要小心缩进（GDScript 靠缩进分层，粘贴时 Tab 和空格混用会直接报错）。**用网页版生成的代码，务必让 CLI 工具或 VS Code 复核一遍缩进。**

### 2.3 针对"不会代码的团队"的推荐组合

### 2.4 三个必看的硬性检查

不管选哪一类，签付费之前**必须确认这三条**，否则钱会白花：

| # | 检查项 | 为什么重要 | 怎么验 |
|---|---|---|---|
| 1 | **能不能直接读写本地文件** | 只能给代码让你粘贴的工具，效率低 5 倍以上，而且缩进错误会浪费大量时间 | 让它"把 `test.gd` 里的第 3 行改成注释"，看它是否真的改了文件 |
| 2 | **能不能执行终端命令** | 能跑 `godot --headless --check-only --script xxx.gd` 才能自己验证，这是本项目技术栈的核心红利 | 让它"运行 `godot --version` 并把输出告诉我" |
| 3 | **有没有 diff 审查界面** | 不会写代码的人只能靠 diff 判断风险。没有 diff 界面，就等于闭眼批准 AI 的所有改动 | 让它改 3 个文件，看能否逐文件、逐行看到 `+`/`-` |

**再加一条中国网络环境相关的**：确认工具**在你的网络下能稳定连上**。部分海外 AI 服务的订阅和调用在国内网络下不稳定，**先买一个月试，确认能稳定用再买年付**（年付虽然便宜，但用不了就全亏）。

## 3. 音频中间件：FMOD 与 Wwise

### 3.1 它们是什么，解决什么问题

音频中间件是插在**游戏引擎**和**音频文件**之间的一层工具。你不用在代码里写"播放这个 wav"，而是写"触发这个事件"，事件内部的随机变体、音量、滤波、切换逻辑都在中间件的可视化界面里配好。

**它真正解决的问题**：一个"挥剑"音效，你希望它每次都不一样（随机 5 个变体 + 随机音高）、受击时按血量降低低通滤波、进 Boss 房自动切战斗 BGM 并平滑过渡。**这些用纯 `AudioStreamPlayer` 写代码能做，但很繁琐；中间件把这些变成拖拽配置。**

|---|---|---|
| 官方授权页 | <https://www.fmod.com/licensing> | <https://www.audiokinetic.com/en/wwise/pricing/>（⚠️ 本文核实当日该页未能成功访问，**请务必以官网为准**） |

### 3.3 小团队到底该不该用？

**结论：前 6 个月不要用。做完第一个可玩版本（能连打 3 段、有 5 种敌人）之后再评估。**

**理由（按重要性排序）**：

1. **免费门槛你们肯定够，但"够免费"不等于"该用"**。FMOD 的 $600k 预算门槛、Wwise 的 $250k 门槛，2-4 人小团队远远低于，所以**钱不是问题**。真正的问题是学习成本和集成成本。
2. **学习成本对初学者是硬伤**。中间件是一套独立的工具链，有自己的概念（Event、Bank、Bus、Snapshot、Parameter）。**你们连 Godot 的节点树都还在学，再加一套中间件的概念，会把学习曲线叠成两倍陡。**
3. **Godot 自带的音频能力对横版动作游戏够用**。`AudioStreamPlayer` + `AudioStreamRandomizer`（随机变体）+ `AudioServer` 的 Bus 和效果器（做低通滤波）+ `Tween`（做淡入淡出），**这四样就能做出 90% 的打击音效需求**。
4. **中间件是给"音频团队"用的**。它的价值在"音频设计师不用碰代码就能改音频逻辑"。你们没有专职音频，这个价值兑现不了。
5. **它会打断 AI 协作闭环**。中间件的事件配置存在二进制工程文件里，**AI 读不了、改不了**。一旦引入，音频相关的改动就必须人工做，AI 帮不上忙——这与你们"AI 为主力"的定位直接冲突。

**什么时候该重新评估**：

- 项目已经能稳定跑起来，且音频需求超过 **50 个音效 + 3 首动态 BGM**；
- 团队里出现了一个愿意专做音频的人，每周能投入 5 小时以上；
- 你发现自己在写第 5 个"手动管理音频变体和淡入淡出"的脚本。

**在此之前，用这个最低成本方案**：

```text
Godot 内置方案：
  AudioStreamPlayer           → 播放单个音效
  AudioStreamRandomizer       → 一个音效配 3-5 个变体，自动随机 + 随机音高
  AudioServer Bus（Master/SFX/BGM）→ 分别控制音量和效果
  AudioEffectLowPassFilter    → 受击/低血量时压低 BGM
  Tween                       → BGM 淡入淡出、平滑切换
```

### 4.1 脚本设计说明

| 设计点 | 为什么这么做 |
|---|---|
| 逐包 `try/catch` + 记录 `$LASTEXITCODE` | **单个包失败不影响其他包**，这是需求里的硬要求。最后汇总表能一眼看出哪个没装上 |
| `--accept-package-agreements --accept-source-agreements` | 不加这两个参数，脚本会卡在"是否同意协议"的交互提示上，无人值守时会一直挂着 |
| `--disable-interactivity --silent` | 批量安装时避免任何弹窗打断 |
| "已安装"靠**输出文本**判断，不靠返回码 | winget 的返回码含义会随版本变化，硬编码某个数字很容易误判。改成匹配输出里的 `already installed` / `已安装` 更稳。**任何判断不准的情况，以汇总表的结果为准** |
| 失败时打印 winget 原始输出 | 大部分失败原因是"需要管理员权限"或"包 ID 变了"，把原文打出来你才能自己修 |
| Godot 默认跳过 | winget 装 Godot 会在更新时覆盖旧版本，**没法保留多版本共存**，与"锁死版本号"的要求冲突。建议手动解压 |
| Aseprite 明确不在清单里 | 已实测确认 **winget 里没有 Aseprite 包**，脚本末尾给出手动下载地址 |
| 末尾提示 `git lfs install` | Git LFS 装了不初始化等于没装，这是初学者最常漏的一步 |

## 5. 下载与网络提示

### 5.1 问题：GitHub 在国内经常慢到没法用

本项目绕不开 GitHub：Godot 的插件、Pixelorama 的发布包、各种工具的最新版都在 GitHub Releases 上。国内直连常见情况是几十 KB/s，或者直接超时。

### 5.2 方案一：GitHub 文件加速代理（下 Release / 压缩包用）

把原始 GitHub 链接前面加上加速前缀即可。以下三个是**第三方公共服务**，2026-10 实测可访问：

| 服务 | 网址 | 特点 | 实测状态 |
|---|---|---|---|
| gh-proxy | <https://gh-proxy.com/> | 支持批量粘贴多个链接一起加速 | ✅ **可用**（真的拉下来一个文件，不只是首页活着） |
| ghproxy | <https://ghproxy.net/> | 支持断点续传 | ❌ **已不可达**（实测超时，别再用） |
| github.akams.cn | <https://github.akams.cn/> | 支持 API / clone / Releases / Archive / Raw | ✅ 首页可达 |

> 状态复核日期：**2026-10-30**。这类第三方服务寿命很短，上表随时会变 ——
> 每次用之前先自己试一下，别把过期的结论当真理。

**用法示例**（下面两行是**格式示意**，`<仓库>/<文件>` 请换成你真正要下载的东西）：

```text
原始链接：https://github.com/<owner>/<repo>/releases/download/<tag>/<file>.zip
加速链接：https://gh-proxy.com/https://github.com/<owner>/<repo>/releases/download/<tag>/<file>.zip
```

⚠️ **重要提醒（必读）**：

1. 这些是**第三方服务，不是 GitHub 官方**。它们能看到你请求的链接，**绝对不要通过它们下载任何私密内容或带 Token 的链接**。
2. 第三方服务随时可能失效或更换域名。**用不了就换一个，或者直接找官网的备用下载点。**
3. **不要**把加速链接写进项目的 `package.json`、脚本或 CI 配置里——一旦服务挂掉，整个项目构建就断了。加速只用于"我手动下载一个文件"这个场景。

### 5.3 方案二：给 Git 本身配代理（clone / pull 慢用）

如果你已经有可用的本地代理（比如本机 7890 端口），让 Git 走代理：

```bash
# 只对 GitHub 走代理（推荐，比全局代理干净）
git config --global http.https://github.com.proxy http://127.0.0.1:7890

# 检查配置是否生效
git config --global --get http.https://github.com.proxy

# 不需要时取消
git config --global --unset http.https://github.com.proxy
```

> 端口号 `7890` 只是常见默认值，**换成你自己代理软件的实际端口**（Clash 常见 7890，v2ray 常见 10809）。不要照抄。

### 5.3.1 方案二之补充：HTTPS 被拦但 SSH 能通（很常见，优先试这个）

国内还有一种比"全都不通"更常见的情况：**`github.com` 的 443 端口 TCP 能握手，但 TLS 之后的数据被拦掉**。
表现是 `git push` 一直卡住直到超时、浏览器打不开 github.com，
但 **SSH 反而是通的** —— GitHub 专门给受限网络准备了 **443 端口的 SSH**（`ssh.github.com:443`）。

**先判断自己属于哪种情况：**

```powershell
# HTTPS：超时 = 被拦
Invoke-WebRequest https://github.com -TimeoutSec 10 -UseBasicParsing

# SSH：看输出里有没有 "successfully authenticated"
ssh -T -p 443 git@ssh.github.com
```

**如果 SSH 通了，把 GitHub 地址全部改走 SSH：**

```bash
git config --global url."git@github.com:".insteadOf "https://github.com/"
```

之后 `git clone` / `git push` 只要写普通的 HTTPS 地址，Git 会自动改走 SSH。

> ⚠️ **两个坑，都踩过：**
>
> 1. `ssh -T git@github.com` **认证成功时退出码也是 1**（它只是告诉你"不提供 shell 访问"）。
>    **不要用退出码判断成败**，要看输出里有没有 `successfully authenticated`。
> 2. 更隐蔽的：Windows PowerShell 5.1 下 `$ErrorActionPreference = 'Stop'` 会把
>    **原生命令写到 stderr 的内容**当成终止性错误。而 ssh 认证成功时恰恰是往 stderr 打印那句话 ——
>    于是脚本在这个"其实成功了"的地方直接中断。写脚本时请用 `'Continue'` + 显式检查 `$LASTEXITCODE`。
>
> 本项目已经踩过这两个坑，相关脚本见 [`tools/push-to-github.ps1`](../tools/push-to-github.ps1)，
> 它会自动探测该走 HTTPS 还是 SSH，也可以单独诊断：`powershell -File tools\push-to-github.ps1 -Diagnose`。

### 5.4 方案三：改用国内可直连的镜像源（针对包管理器）

有些东西不需要走 GitHub，直接换源更快：

```bash
# npm（Node.js 包）换成淘宝镜像
npm config set registry https://registry.npmmirror.com

# pip（Python 包）换成清华镜像
pip config set global.index-url https://pypi.tuna.tsinghua.edu.cn/simple
```

### 5.5 方案四：Godot 本体走官方 CDN

**Godot 的下载不经过 GitHub**，走的是官方 `downloads.godotengine.org`，在国内速度通常可以接受。所以：

- **优先用官网下载页**：<https://godotengine.org/download/windows/>
- 只有**插件和工具**（比如 GUT 测试插件、Pixelorama 的更新包）才需要走 GitHub 加速。

### 5.6 下载前必做的两件事

1. **核对文件大小和校验值**。GitHub Release 页面通常会给出文件大小；Godot 官方下载页也有。**下载下来的文件大小明显不对（比如 3 MB 而不是 60 MB），就是被代理截断了，重新下。**
2. **不要在公共 Wi-Fi / 公司网络下用不明代理**。加速服务会看到你的请求 URL，涉及账号相关的链接一律走官方直连。
