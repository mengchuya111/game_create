## 1. 核心原则

### 1.1 你们验收不了"代码写得对不对"，但完全可以验收"行为对不对"

这不是安慰，是分工。

**"代码写得对不对"** 指：类的职责放对了吗？依赖注入顺序以后会不会出事？同屏 200 个敌人会不会卡？——判断这些需要工程经验，你们没有，**也不需要**。这部分交给 [AGENTS.md](../AGENTS.md) 的架构规矩去约束（纯逻辑进 `RefCounted`、血量只走 `Hurtbox.receive_hit`、判定盒显式声明阵营、禁止全局随机、手感数值不硬编码）。规矩守住了，架构就不会跑偏。

**"行为对不对"** 指：我按 `J`，角色有没有砍出去？砍中的那一帧画面有没有冻结 4 帧？换房间之后回放里的角色还在不在动？——判断这些**只需要一双眼睛、一个键盘和一张对照表**。

所以一条验收用例的形状是固定的三件套：

| 要素 | 说明 | 反例 → 正例 |
|---|---|---|
| **一个操作** | 精确到按键、命令、位置、帧 | ❌"试一下冲刺" → ✅"站在山贼正前方 30 像素处，按 `L`" |
| **一个可观测信号** | 屏幕上能看到的、HUD 能读到的、命令能打印的、退出码能表示的 | ❌"感觉变快了" → ✅ HUD 的"状态 RUN"、`pos` 打印的速度 |
| **一个期望值** | 一个具体数字、一个布尔、一段文本 | ❌"应该正常" → ✅"速度 = 190" |

**判断标准**：如果你写不出"可观测信号"，说明这个需求还没想清楚，先别派给 AI。

### 1.2 三件必须提前说清的事

1. **验收用例必须在 AI 动手之前写。** 写晚了，你会不自觉地按它的实现来验收——那不叫验收，叫确认。[00-学习路线.md](00-学习路线.md) 误区 2 的结论：**没写用例的功能不算做完，只算"写完了"。**
2. **每条用例至少配 2 条反向用例**（问"**不该发生什么**"）。本骨架真实抓到的 3 个 bug 里，有 2 个（敌人误伤、换房丢输入）只有反向用例才能发现。
3. **证据必须是"可复制的"**：一段命令输出、一个种子、一份重放文件、一段录屏。队友照着能复现的才算证据。

## 2. 四层验收手段

四层是**叠加**关系，不是替代关系。**四层都过才算验收通过；缺任何一层，就有一整类问题没人管。**

| 层 | 谁跑 | 耗时 | 能抓到 | 抓不到 |
|---|---|---|---|---|
| ① 单元测试 | AI 自己跑 | 几秒 | 公式、状态机、帧数据合法性、房间生成、重放序列化 | 节点路径、信号连线、装配顺序、手感、画面 |
| ② 冒烟测试 | AI 自己跑 | 十几秒 | 接线错误、阵营错误、换房丢数据、穿模、出界、相机脱挂 | 手感、画面、只在别的种子下才出现的问题 |
| ③ 游戏内调试台 | 人手动 | 5-30 分钟 | 具体行为、单招手感、数据表配置错误、指定局面的复现 | 精确帧数的时序、长时间稳定性 |
| ④ 录屏 / 重放文件 | 人 | 5 分钟 | 可复现的证据、逐帧对比、交给 AI 精确复现 | 重放只有输入没有画面；录屏不会自动断言 |

### 2.1 ① 单元测试：纯逻辑层，约 70% 的回归 bug 在这里被挡住

```powershell
cd D:\dream_start
& ".tooling\Godot_v4.7.2-stable_win64_console.exe" --headless --path game --script res://tests/run_tests.gd
```

实测输出（本文写作时的真实结果）：`测试套件 11 个   测试方法 225 个   断言 1407 条   失败 0 个` / `结果：全部通过 ✓`。11 个套件（清单在 `game/tests/run_tests.gd`）覆盖的正是"能写成纯逻辑的东西"：

| 套件 | 覆盖什么 |
|---|---|
| `test_player_fsm.gd` | 状态机、连段、取消窗口、输入缓冲、土狼时间、受击/死亡 |
| `test_attack_table.gd` | 帧数据字段约束、`cancel_into` 指向的招式必须存在、注释键跳过 |
| `test_damage.gd` | 伤害公式、防御减伤、连段衰减、架势结算、击退重量 |
| `test_hitstop_shake.gd` | 顿帧计时（含"取最大值不叠加"）、震屏 trauma 衰减 |
| `test_room_generator.gd` | 房间路线生成、合法性校验、连通性、同种子可复现 |
| `test_replay_recorder.gd` | 输入位掩码编解码、文件读写、格式版本校验、越界容错 |
| `test_deterministic_rng.gd` | 确定性随机数：同种子同结果、不泄漏全局状态 |
| `test_run_state.gd` | 局内成长：心法叠层、属性总和的"整表重算"、封顶、内力结算 |
| `test_upgrade_pool.gd` | 心法池加载与校验、稀有度权重、三选一可复现、未知效果键拦截 |
| `test_room_data.gd` | 房间模板 × 敌人表**跨表校验**（含"打不死的敌人不得进清房房"，见 AGENTS 陷阱 8） |
| `test_shop.gd` | 商店摆货、按稀有度定价、购买扣内力、重复购买被拒 |

**抓不到什么**：这些测试全部 `new()` 出来就能跑，**根本不知道场景树存在**。所以 `$Hurtbox` 路径写错、信号忘了 `connect`、换房后相机绑在旧节点上、装配顺序不对——它一个都发现不了，**这类问题一律归 ② 管**。

**读输出时的纪律**：控制台里会夹着 `ERROR:` / `WARNING:`，那是单元测试**故意**喂错误数据造成的（[AGENTS.md](../AGENTS.md) 陷阱 5 列了清单，如 `[AttackTable] 帧数据表里一条有效招式都没有`、`重放格式版本不匹配：文件是 999`、`找不到重放文件`）。**只看最后两行和退出码**，不要试图"修掉"这些报错。

### 2.2 ② 冒烟测试：真的把游戏跑起来，抓接线错误

```powershell
& ".tooling\Godot_v4.7.2-stable_win64_console.exe" --headless --path game res://tests/smoke_run.tscn
```

实测输出：`检查项 96 个   失败 0 个` / `结果：冒烟测试全部通过 ✓`。它做五件事：

| 阶段 | 做什么 | 专门验证什么 |
|---|---|---|
| 1 | 用脚本化输入自动玩 **600 帧**（固定种子 `20240501`）：原地不动 → 纯跑动 → 边跑边连招 → 转身往回跑；第 300 帧跳跃、第 420 帧冲刺 | 状态覆盖、判定盒真的开过、招式三阶段都报告过、不穿模、相机不脱挂、房间能推进 |
| 2 | **被动挨打**：交出控制权，站到山贼面前 30 像素处什么都不按，最多等 360 帧 | "敌人 → 玩家"这条**反向链路**：AI 出招 → 判定盒 → 受击盒 → 掉血 → HURT 状态 |
| 3 | 走**调试台的正式注册表**执行命令 + 存读一份重放文件 | 31 条命令全部注册、无副作用命令都有输出、`check` 无 ✗、`dump` 是合法 JSON、重放帧数/种子一致 |
| 4 | **清房 → 三选一 → 自动进下一间**（走真实流程，不调用测试钩子） | 成长系统与换房的**协程时序**：清房后是否真的给奖励、`await` 会不会永久挂起、换房后血量与生命上限有没有被继承、HUD 心法栏显示的是中文名还是原始 id |
| 5 | **走进商店房 → 自动开商店 → 离开 → 进下一间** | 内力消费链路：进商店房是否自动开面板、开面板时输入有没有被锁、离开后是否解锁并推进 |

**跑一次你会看到的观测数据**（实测）：`状态覆盖 IDLE, FALL, RUN, ATTACK, HURT`、`判定盒开启 56 帧`、`命中 21 / 敌人掉血 18 / 玩家受伤 3`、`最大顿帧 8 帧 / 最大震动强度 1.000`、`清空房间 4 次 / 访问房间 3 间`、`三选一 给出 2 次 / 结算 2 次`。**这组数字本身就是验收证据**：命中次数变成 0 → 战斗链路断了；访问房间数变成 1 → 换房断了；最大震动强度变成 0 → 震屏没接上；"给出 2 次但只结算 1 次" → 奖励协程泄漏了。

**抓不到什么**：**手感**（它只能断言"顿帧请求了 8 帧"，不能断言"这 8 帧打起来爽不爽"）；**画面**（`--headless` 不渲染，"贴图闪不闪""血条会不会缩"一律验不到）；**别的种子**（它固定用 `20240501`，要覆盖种子只能靠人手动换种子玩）；**它自己输入脚本之外的情况**（脚本是"为了覆盖而设计"的，不是随机乱按）。

### 2.3 ③ 游戏内调试台：人手动验证具体行为

```powershell
& ".tooling\Godot_v4.7.2-stable_win64_console.exe" --path game
```

按 `` ` `` 或 `F1` 打开。这是**团队验收的主要工具**（[AGENTS.md](../AGENTS.md) 第 10 节），31 条命令的验收用途：

| 命令 | 验收时用来干什么 |
|---|---|
| `seed 20240501` + `restart` | **每次验收的第一步**：固定种子，让"同一局面"可以反复复现 |
| `rooms` / `next` / `tp 120 180` | 看这一局的 8 间路线；`next` 直接跳下一间（**验收最常用**，不用真打过去）；`tp` 把角色精确放到某个坐标（例如山贼正前方 30 像素处） |
| `hp 50` / `god` | 造局面；测伤害时**必须确认 `god` 是关的** |
| `pos` | 读位置、速度、状态名、状态帧、连段序号——**帧级验收靠它** |
| `attack light_2` | 把起手招式换成某一招，单独测这一招的手感 |
| `check` / `attacks` / `data light_1` | 校验全部数据表（有 ✗ 就是配错了）；列招式帧数与取消窗口；打印单招完整帧数据 |
| `dump` | 导出当前局面 JSON（种子/房间/玩家/敌人）——**提 bug 时贴给 AI 的最佳材料** |
| `save` / `replays` / `replay <文件名>` | 把出问题的一局存下来、列出来、放回去 |
| `hitstop 8` / `shake 0.5` / `feel` | 手动触发顿帧/震屏；`feel` 依次播放 2/4/6/8 帧顿帧，专门调手感 |
| `help` / `clear` / `hide` / `quit` | 查命令、清屏、关面板、退出 |

另外两个验收界面：**HUD（`F2` 开关）** 实时显示 FPS、种子、房间、血量、架势、状态名、状态帧、朝向、连段序号、当前招式与阶段（起手/判定/收招）、无敌帧、顿帧、震动强度、场上敌人数；**贴图闪烁**（无敌期间每 70 毫秒在 0.4/1.0 之间切）是唯一能"看见"无敌帧的方式。

**抓不到什么**：精确帧数（肉眼数不出"第 19 帧还是第 20 帧"，要用 ④ 逐帧看）；长时间表现（手动玩 10 分钟就开始随便点点）；它自己的可靠性（所以冒烟测试阶段 3 会替你把 31 条命令跑一遍）。

### 2.4 ④ 录屏 / 重放文件：可复现的证据

**重放文件**（游戏内 `save` 生成，落在 `user://replays/`，Windows 上是 `%APPDATA%\Godot\app_userdata\武侠肉鸽 · 可验证骨架\replays\`）：格式是 `{ version: 1, seed, frame_count, note, frames }`，`frames` 里每帧只占一个整数（输入位掩码），文件极小，可以直接发给队友或贴给 AI。**它的价值是"精确回到出问题的那一帧"**——bug 出现在"第 47 秒、第 3 间房、山贼冲过来的瞬间"时，靠嘴巴描述谁都复现不了，靠一个种子 + 一份输入记录谁都能复现。

**录屏**（[01-工具清单.md](01-工具清单.md) 把它列为"必须装"：手感调优靠它逐帧看）：解决"帧数"和"画面"这两个重放解决不了的问题。60 FPS 录屏逐帧前进，能直接看到"判定盒比动画早了 2 帧""顿帧期间画面完全冻住了"。

**抓不到什么**：重放**只有输入没有画面**，不能当录屏用，也不能自动断言（断言靠 ① 和 ②）；重放带格式版本号（当前 `FORMAT_VERSION = 1`），版本不匹配会读不出来（返回 null 并给警告），所以别把它当长期存档；录屏不会替你判断对错，**录之前先把期望写下来**。

## 3. 把模糊需求变成可执行用例（3 个实例）

模糊需求的共同点是"没有可观测信号"。下面三组把同一句模糊的话翻译成能贴进 issue 的用例。**每组的反向用例都不少于 2 条。**

### 3.1 "打击感要好" → 轻击一段命中

**为什么不可验收**：没说打什么、没说哪一帧、没说哪里体现。

| # | 操作 | 期望 | 怎么确认 |
|---|---|---|---|
| 1 | `seed 20240501` → `restart` → `next` → `tp` 到目标前 → 按 `J` | 判定盒在**第 7/8/9 个 tick** 开启（`state_frame` 6/7/8） | HUD 显示"招式 轻击·一段 判定 7/19 帧" |
| 2 | 命中瞬间 | 顿帧请求 **4 帧**（`light_1.hitstop = 4`）；期间 `time_scale = 0.05`；结束后必须回到 **1.0** | HUD"顿帧 x/4 帧"；`dump` 的 `time_scale`；冒烟测试也有这条断言 |
| 3 | 命中瞬间 | 震动峰值 0.22² ≈ **0.048**（HUD 显示 trauma²），按 **3.2/秒**衰减完（0.22 ÷ 3.2 ≈ 0.069 秒 ≈ **4.1 帧**） | HUD"震动 0.05" → 回到 0.00 |
| 4 | 命中山贼 | 掉血 **7 点**（`damage 8`，山贼 `defense 10` → 8 × 100/110 ≈ 7.27 → 7） | `dump` 里敌人 `hp` 从 60 变 53 |

**反向用例**：

| # | 操作 | 不该发生什么 | 怎么确认 |
|---|---|---|---|
| R1 | 站在远离目标处按 `J` | 不顿帧、不震屏：`requested_frames()` 保持 0，`intensity()` 保持 0，`time_scale` 始终 1.0 | HUD 的顿帧/震动两行全程 0 |
| R2 | 一次挥击打中同一个山贼 | 判定盒开 3 帧，但**只掉一次血**（60 → 53，不是 60 → 39） | `dump` 对比前后 `hp`；这是"3 帧判定打出 3 倍伤害"这个新手 bug 的专门防线 |
| R3 | 一次挥击同时打中 3 个目标 | 顿帧是 **4 帧**（取最大值），不是 12 帧 | HUD"顿帧 4/4 帧" |
| R4 | 打中训练木桩 | 不该触发"敌人误伤"计数（木桩不该被敌人砍死） | 冒烟测试的"敌人没有互相误伤"一项 |

> ⚠️ 第 4 条的前提：**测伤害前先确认 `god` 是关的**。`god` 打开后玩家 `invuln_frames = 1 << 30`，任何伤害都测不出来。

### 3.2 "冲刺要能躲招" → 冲刺无敌帧与冷却

| # | 操作 | 期望 | 怎么确认 |
|---|---|---|---|
| 1 | 站在地面按 `L` | 冲刺持续 **11 帧**（`DASH_FRAMES`），速度 **430 px/s**（`DASH_SPEED`）朝当前朝向；`hurtbox.invuln_frames` 抬到 **11**；贴图每 **70 毫秒**在 0.4 / 1.0 之间闪 | `pos` 速度 ≈ 430；HUD 出现"无敌帧 N"；肉眼可见在闪 |
| 2 | 冲刺前 11 帧内被打中 | **不掉血** | HUD 血量不变；`dump` 里 `hurtbox.hp` 不变 |
| 3 | 冲刺结束后再按 `L` | **24 帧**（`DASH_COOLDOWN_FRAMES`）冷却内无效 | 连按 `L`，`pos` 的速度不会连续两次到 430 |
| 4 | 冲刺中撞墙 | 不穿墙、不卡进墙里 | `pos` 坐标仍在房间内（墙在 `±(room_width/2 + 10)`，`room_width = 1280`） |

**反向用例**：

| # | 操作 | 不该发生什么 | 怎么确认 |
|---|---|---|---|
| R1 | 冲刺开始后第 12 帧被打中 | **应该掉血**（无敌帧已耗尽） | 血量减少 10（`enemy_swipe.damage = 10`，玩家 `defense 0`） |
| R2 | 冷却期间反复按 `L` | 不该速度叠加、连冲、动画卡死 | `pos` 速度不超过 430 |
| R3 | 受击硬直（HURT）中按 `L` | 不该冲刺（`can_dash()` 在 HURT 返回 false） | HUD 状态保持 HURT |
| R4 | 冲刺中按 `J` 或空格 | 不该出招、不该二段跳 | HUD 状态不切到 ATTACK / JUMP |

### 3.3 "房间推进要顺" → 清空与换房

| # | 操作 | 期望 | 怎么确认 |
|---|---|---|---|
| 1 | `seed 20240501` → `restart` → `rooms` | 打印 **8 间**（`ROOM_COUNT = 8`），第一间 START（0 敌人）、最后一间 BOSS | `rooms` 输出 |
| 2 | 清光当前房间所有敌人 | 触发 `room_cleared`，**0.9 秒**后自动进入下一间 | 调试台出现 `[流程] room_N 已清空` 和 `[房间] N/8 …` |

> ⚠️ **两个必须知道的坑（都核实过，不是猜测）**：
>
> 1. **`GameConfig.HURT_INVULN_FRAMES = 30` 目前没有被任何代码读取。** 真正生效的是 `player.tscn` 里 Hurtbox 的 `invuln_frames_on_hit = 30`。同一个数值有两处定义，**你改 `game_config.gd` 里那个不会有任何效果**。验收受击无敌帧时以 `player.tscn` 为准。
> 2. **`enemies.json` 里 `training_dummy` 的 `weight: 2.0` 没有被读取。** `enemy.gd` 的 `apply_archetype()` 只应用了 `behavior / max_hp / defense / move_speed / detect_range / attack_id / attack_interval_frames / respawn_delay`，**没有 `weight` 和 `max_poise`**。所以木桩的击退表现和 `weight 1.0` 的敌人一样。**改了 `weight` 发现没变化，不是你的错觉，是那个字段还没接线。**
>
> 另外：[00-学习路线.md](00-学习路线.md) 阶段 4 那张"可直接照抄的起始数值"表（轻击 1 是 5/3/8、顿帧 2）是**建议起点**，和当前 `attacks.json` 的实测值（6/3/10、顿帧 4）**不完全一致**。验收时一律**以 `attacks.json` 为准**。

### 6.3 调参纪律

1. **一次只改一个数字，改完打 10 下感受一下，再改下一个。**（`attacks.json` 的 `_readme` 原文）
2. **改帧数据之后必须跑 `test_attack_table.gd`**（跟着 `run_tests.gd` 一起跑）：它校验 `startup ≥ 1`、`active ≥ 1`、`recovery ≥ 0`、`cancel_from` 的合法区间、以及所有 `cancel_into` 指向的招式真实存在。
3. **改完跑一遍 `check`**（有 ✗ 就是配错了），**再重跑冒烟测试**（帧数据直接影响"判定盒开过几帧""命中次数""最大顿帧"这些观测值）。
4. **调参前先 commit。** 手感调参是反复试错，没有回退点你不敢乱试。
5. **调完把新数值更新回本文档第 5、6 节的表。** 文档和数据的偏差比没有文档更糟。

## 7. 常见"假通过"

每一条都会让验收**失效**——测试是绿的，功能是坏的。

| # | 假通过 | 为什么会失效 | 怎么防 |
|---|---|---|---|
| 1 | **只测了玩家打敌人，没测敌人打玩家** | 这正是真实抓到 `source_team` bug 的原因：山贼打不到玩家、却互相误伤砍死木桩，而"玩家打敌人"这条链路完全正常 | 冒烟测试阶段 2 专门做"被动挨打"；自己验收也要站着挨一次打 |
| 2 | **只跑了一次，没固定种子** | 路线和敌人位置随种子变，第二次条件就不同了 | 每次验收先 `seed 20240501` + `restart` |
| 3 | **AI 说"测试通过了"但没贴输出** | 无法判断它跑没跑、跑的哪条命令、什么时候跑的 | 一律要求贴**完整输出**（[02-AI协作工作流.md](02-AI协作工作流.md) 第 7.2 节） |
| 4 | **只贴了最后一行** | `225 → 217` 也是"全部通过"，但测试被删了 | 认最后**两**行：结论行 + 数字行 |
| 5 | **只测正常路径，没测边界** | 第 19 帧 vs 第 20 帧、第 11 帧 vs 第 12 帧、距离 33 vs 34——off-by-one 全在边界上 | 每条用例配 2 条反向用例，专门打边界 |
| 6 | **只跑 headless，没开窗口** | 画面、闪烁、血条、颜色、镜头全没验 | 必须开一次 `--path game` 亲手玩 |
| 7 | **改了数据但没跑 `check`** | 数据表配错了 `check` 会打 ✗，但没人看 | 改任何 `data/*.json` 后第一件事就是 `check` |
| 8 | **把"预期错误"当成失败去"修掉"** | 单元测试故意喂错误数据，那些 `ERROR:` 是设计的一部分 | 只看最后两行和退出码（[AGENTS.md](../AGENTS.md) 陷阱 5） |
| 9 | **开着 `god` 验收伤害** | `invuln_frames = 1 << 30`，什么都测不出来 | 测伤害前先敲一次 `god` 确认是"关" |
| 10 | **在错误的房间/位置验收** | 起点房没有敌人；山贼 34 像素内才出招，站远了它只会走过来 | 用 `next` 进战斗房、用 `tp` 精确站位 |
| 11 | **验收用例是 AI 写的** | 它只会测自己实现的那条路（"能打中就通过"） | 用例由人写，AI 只负责实现和补单元测试 |
| 12 | **改了数据字段，但那个字段根本没被代码读取** | 真实例子：`weight`、`max_poise` 没被 `apply_archetype()` 读取；`GameConfig.HURT_INVULN_FRAMES` 没被任何代码引用。改完游戏里毫无变化 | 改数据前先确认"这个字段谁在读"；改完必须**肉眼看到变化**，看不到就是没接线 |
| 13 | **用 `Engine.time_scale` 判断顿帧却忘了它会被自己缩放** | 顿帧期间 `delta` 也被缩放，用 `_process(delta)` 直接倒数会变成 20 倍时长 | 认 `combat_director.gd` 里除以 `time_scale` 的写法（[AGENTS.md](../AGENTS.md) 陷阱 1） |
| 14 | **只看 diff 不看行为** | diff 里"少了一行"（比如 `hitbox.source_team = "enemy"`）肉眼极难发现 | diff + 冒烟测试双保险，缺一不可 |
