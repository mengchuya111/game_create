# 监管打卡 App

一个给自己用的每日打卡工具。**手机和电脑访问同一个地址，数据共享** —— 在手机上打的勾，电脑上刷新就能看到。

预置了 10 条清单（7 条每日 + 3 条每周），内容来自 [docs/02](../02-AI协作工作流.md) 和
[docs/03](../../docs/03-验收清单.md) 里"监管每天该做什么"的浓缩版。所有条目都可以在界面上改。

---

## 怎么启动

双击 **`start.cmd`**，或者在 PowerShell 里：

```powershell
node tools\checkin\server.js
```

启动后终端会打印两个地址：

```
  本机（电脑）：  http://localhost:8080
  手机/平板：     http://10.117.12.11:8080      <- 手机浏览器打开这个
  数据文件：      D:\dream_start\tools\checkin\data.json
```

**手机和电脑必须连同一个 WiFi。**

想把 App 放到手机桌面：在手机浏览器里打开上面那个地址 → 菜单 → "添加到主屏幕"。
之后点图标就能直接进，跟原生 App 差不多。

---

## 数据存在哪 / 怎么备份

所有数据都在 **`data.json`**，就在这个目录下，纯文本，可以直接用 VS Code 打开看、改、备份。

这个文件**不进 git**（已在 `.gitignore` 里），因为它是你的私人打卡记录，不该推给别人。

备份有两个办法：

1. **复制 `data.json`** —— 最直接
2. **点界面右下角「导出」** —— 把 JSON 复制走；换手机/重装浏览器后用「导入」恢复

> ⚠️ 导入会**覆盖**当前所有清单和记录，导之前先导出一次备份。

## 安全说明（请读一下）

**这个 App 没有任何密码或登录。** 任何能连到你局域网的人，只要知道地址和端口，就能看到
甚至改掉你的打卡记录。

对"自己监督自己"这个场景通常无所谓，但你要知道它的边界：

- ✅ 适合：家里/公司同一个 WiFi，只有你自己用
- ❌ 不适合：连公共 WiFi、或者你想从外网访问（那需要自己做认证或加 HTTPS）

另外你这台机器的 **Windows 防火墙三个配置都是关闭的**（Domain / Private / Public 全 False）。
这不是本 App 改的，是本来就这样。防火墙关着的时候手机才能连进来，但也意味着别的端口同样对外暴露。
要不要开防火墙是你的安全策略选择，我在这只提一句。

## 它有什么功能

| 功能 | 说明 |
|---|---|
| 每日 / 每周两栏 | 今日完成百分比只算「每日」那栏；每周的项不参与每日百分比 |
| 进度环 | 全部做完变绿 |
| 连续打卡天数 | 从今天往回数，「每日」项全做完才算一天。今天还没做完不算断 |
| 历史热力图 | 最近 60 天，每格显示当天完成百分比 |
| 备注 | 每天一条自由文本，记复盘想法 |
| 编辑清单 | 左下角 ✎ 进入编辑，可增删改、切换每日/每周 |
| 导出 / 导入 | 换设备或备份用 |
| 自动同步 | 每 5 秒拉一次，两台设备自动对齐；切回前台立刻同步 |

## 为什么是这么设计的

三个刻意的选择，都是为了"别让它成为负担"：

**1. 为什么需要服务器，不能纯前端？**
纯 localStorage 的话，手机和电脑各存各的，永远对不上。而"用 App 监督自己"的前提恰恰是
两台设备看到同一份记录。所以数据必须放在一个共享的地方 —— 就是一个 JSON 文件。

**2. 为什么不用框架？**
整个应用一个人用、数据量极小。上 Express 只会多一个 `npm install` 的步骤，而这个项目的第一原则是
"队友克隆下来就能跑"。所以 `server.js` 只用 Node 自带的 `http` / `fs` / `path` / `os`。

**3. 为什么前端全内联在一个 HTML 里？**
手机可能连不上外网，不能依赖任何 CDN；而且没有构建步骤，改一行刷新就能看到效果。

## 常见问题

**手机打不开？**
1. 确认手机和电脑在同一个 WiFi
2. 确认用的是**局域网地址**（`10.117.12.11:8080`），不是 `localhost`（手机上 localhost 指手机自己）
3. 确认 `start.cmd` 那个窗口还开着 —— 关掉窗口服务就停了
4. 电脑换了 WiFi 或重连后 IP 可能变，重新启动服务看终端打印的新地址

**两台设备数据不一样？**
往下拉一下、或者点右下角「已同步」按钮强制拉一次。还不对就说明有一台的写入失败了，
看终端有没有报错。

**`data.json` 变成乱码 / 打不开？**
服务启动时会检查，解析失败会备份成 `data.json.broken-<时间戳>` 然后从默认清单重新开始。
把坏文件发给 AI 看，或者直接用备份恢复。

**端口被占用？**
换个端口：`node tools\checkin\server.js --port 8090`，然后访问 `http://IP:8090`。
